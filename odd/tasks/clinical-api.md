## Specs
- S1: “API con validación de entrada (FastAPI + Pydantic). Los endpoints mínimos serían POST /evaluaciones y GET /astronautas/{id}/historial.” “Un sexo=\"X\" o una fase \"marte\" se aceptan en silencio.” “Una PAS de −5 se acepta y da ALTO.” “Un NaN en FR da 3 puntos solo por accidente de las comparaciones, no por diseño.” “ciclo=\"suprimido\" con fase_ciclo=\"lutea\" no da error.” “Valida en la frontera (rangos fisiológicos, enums, coherencia ciclo/fase) y rechaza con error claro.” Test public API and direct domain rejection; current reproduction gives MEDIO for negative PAS and NaN FR, but silent acceptance is confirmed.
- S2: “Persistencia (SQLite o Postgres). Tablas mínimas: astronauta, perfil, línea base (general y por fase), mediciones con timestamp, evaluaciones y alertas. Guarda con cada resultado la versión de las reglas para poder reproducirlo.” Store immutable configuration, profile, baseline and engine identifiers with results; explicit initial schema setup, no automatic destructive migration.
- S3: “Servicio de línea base personal. Hoy LineaBase se pasa a mano. Falta calcularla desde las mediciones preflight (mediana, mínimo de muestras, manejo de outliers) y por fase del ciclo. También falta actualizarla cuando cambie el peso.” Use comparable current-profile preflight observations, median/MAD filtering, configurable retained minimum; new mass creates a profile revision and invalidates old baseline rather than fabricating vitals from weight.
- S4: “Umbrales en configuración versionada. DESV, los offsets (+0.4 °C, +6 lpm) y los multiplicadores están fijos en el código. Muévelos a YAML o a la base para calibrarlos sin tocar código.” Keep absolute NEWS2 unchanged; snapshot and hash validated calibration config, no silent version reuse with different bytes.
- S5: “Derivar la fase del ciclo. Hoy quien llama debe pasar \"lutea\". Un servicio con fecha de última menstruación y duración del ciclo la calcularía. Trata esos datos como sensibles.” Calendar output explicitly estimated; no assertion of observed ovulation. Sensitive dates encrypted, no PHI in errors/audit. Estimation must not silently enable phase-specific physiological adjustments.
- S6: “Lógica temporal. Evalúas una sola foto. Faltan la tendencia del NEWS2, exigir N lecturas seguidas antes de alertar (menos falsas alarmas) y avisar si no hay mediciones en X horas.” Configurable trend/debounce/overdue; preserve immediate high acute risk and NEWS2 urgent safety floor, serialize chronological observations. Monitoring command/endpoint must actually create overdue alerts without requiring a new measurement.
- S7: “Ciclo de vida de alertas. Estados nuevo, reconocido y resuelto, con destinatario (astronauta, oficial médico, tierra) y registro de quién respondió.” Explicit role-aware transitions with actor/time, no silent reset or duplicate active alert.
- S8: “Roles y auditoría. Son datos de salud: permisos por rol y bitácora de accesos.” User selected “Servidor con datos reales” and “OIDC externo (recomendado)”. Verify issuer/audience/signature/expiry, no token-selected roles, server-managed astronaut assignments; authorized and denied accesses audited without payloads/tokens. No remote probes or credential reuse.
- S9: “Más tests. Los actuales cubren casi solo el cribado. Faltan límites exactos de las tablas NEWS2 (90/91, 95/96), contextos (ciclo, regreso a gravedad, EVA), umbrales de CO₂ y entradas inválidas. Ya hay Riesgo y evaluar listos para eso.” Pin behavior at boundaries and compare valid legacy behavior with baseline; security and transaction tests use synthetic isolated state.
